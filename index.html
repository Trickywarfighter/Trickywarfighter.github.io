These three projects were built in order over two years, and each one asked for something the last one didn’t. The platformer taught me scripting. The canyon shooter added 3D modelling and terrain. The FPS needed a level designed on paper first, then built in Blender from scaled drawings.

Everything below is my own work. Where I used environment or character assets from the Unity Asset Store or Sketchfab, I’ve said so.

Obstacle Course Platformer

Unity · C#

A jumping course where the player crosses moving platforms to reach the finish. My first Unity build, and where I learned to write and debug C# from scratch.

What I built

  • Designed the level layout, then built the map in Unity
  • Applied colours and materials across the course
  • Tested each obstacle in play mode and fixed what broke

Scripts I wrote

  • Spinner — rotates an obstacle continuously from X, Y and Z values set in the Inspector
  • PlayerMoveJumpHit3D — movement and jumping, turning objects yellow on collision while excluding the ground
  • Restart — reloads the scene when the player hits a trigger, restarting the level

Spaceship Canyon Shooter

Unity · Terrain Tools · C#

Fly a ship through a canyon, firing lasers and staying inside the boundaries. This is where I started designing on paper before touching the engine.

What I built

  • Drew the ship by hand first — thrusters, cockpit, power, main systems, and an arrowhead nose for aerodynamics — then modelled it
  • Sculpted the canyon using Unity Terrain Tools and post-processing
  • Designed the main menu on paper, then built it with working buttons and hover colours

Scripts I wrote

  • ShipController — movement, rotation and laser fire, keeping the player inside the play area
  • PlayerControls — flight in all directions, ship roll based on movement, and firing at enemies

Zombie Survival FPS

Unity · Blender · C#

A first-person survival horror game set after a zombie outbreak — survival, horror, apocalypse. The biggest of the three, and the only one where I designed the level as technical drawings before building it.

What I built

  • Drew a ground plan and scaled wall elevations for an L-shaped garden level
  • Modelled that level in Blender — extruded the floor plan into walls, applied materials, set up lighting for atmosphere
  • Chose an L-shape deliberately: the player can’t see round the corner, which builds tension
  • Built the main menu and set up the player controller as a prefab
  • Wrote the design documentation — concept, MDA framework, and the protagonist’s motivation and backstory

Scripts I wrote

  • FPSController — first-person movement, mouse look, and gravity so movement feels weighted
  • Weapons — shooting with single, burst and automatic fire modes, plus bullet spread for realism
  • BulletImpact — detects hits, spawns an impact effect, cleans up the bullet, and shatters bottles when they’re shot

A bug I fixed

  • The rifle pointed the wrong way no matter how I rotated it. I fixed it by parenting the model to an empty object and rotating that instead.

Research & Analysis

Written portfolio

The portfolio wasn’t only building. Roughly half of it was written research, graded at Distinction for Informing Ideas and Communication.

  • Accessibility and inclusive design — the barriers players with visual, hearing, mobility and cognitive impairments face, and what modern games do to remove them
  • UI and UX evaluation — comparing what works and what doesn’t across released commercial games
  • Player motivation — Maslow’s hierarchy of needs applied to how games hold attention
  • Conditioning and reward design — Pavlov and Skinner, and how reward loops shape play
  • Game addiction — what turns a hobby into a problem, and how design decisions contribute
  • Design documentation — concept, MDA framework, character motivation, ground plans and scaled elevations

All code, level design, 3D modelling and written work here is my own. Environment, character and weapon assets were sourced from the Unity Asset Store and Sketchfab and are credited to their creators.
